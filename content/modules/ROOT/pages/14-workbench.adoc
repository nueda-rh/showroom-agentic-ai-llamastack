= OpenShift AI Workbenchのセットアップと使用

このワークショップの演習を実行するためのもう一つのアプローチは、Jupyter Notebook、R Studio、またはVisual Studio Code Serverの開発環境を提供するRed Hat OpenShift AIのWorkbench機能を使用することです。

このワークショップの主な対象者はアーキテクト、プラットフォームエンジニア、開発者であるため、スクリーンショットにあるようにCode Serverのアプローチを採用します。

[TIP]
====
*なぜWorkbenchを使用するのですか？* Showroomのターミナルはコマンドの実行には適していますが、Workbenchを使用するとクラスター内で完全なIDE体験が得られます。Pythonスクリプトの閲覧や編集、ブレークポイントの設定、複数のファイルを並べて開くことが可能です。これはお客様のネームスペース内のポッドとして実行されるため、他のワークロードと同様にLlama StackやMCPサービスへのネットワークアクセスが可能です。
====

== Helm

このワークショップでは *helm* CLIを使用しますが、デフォルトではCode Server Workbenchに含まれていないため、インストールする必要があります。

[.console-input]
[source,bash,role="copypaste",subs=attributes+]
----
mkdir -p $HOME/bin
cd $HOME/bin

curl -fsSL https://get.helm.sh/helm-v3.14.4-linux-amd64.tar.gz | tar -xz
mv linux-amd64/helm .
chmod +x helm

export PATH="$HOME/bin:$PATH"
----

[.console-input]
[source,bash,role="copypaste",subs=attributes+]
----
helm version
----

[.console-output]
[source,bash,subs=attributes+]
----
version.BuildInfo{Version:"v3.14.4", GitCommit:"81c902a123462fd4052bc5e9aa9c513c4c8fc142", GitTreeState:"clean", GoVersion:"go1.21.9"}
----

演習を開始する前に、$HOME に戻っていることを確認してください。

[.console-input]
[source,bash,role="copypaste",subs=attributes+]
----
cd $HOME
----

Workbenchのセットアップが完了しました。xref:02-llamastack.adoc[Llama Stackのデプロイ] に進んでください。

== トラブルシューティング (Troubleshooting)

OpenShift AIコンソール内でプロジェクト/ネームスペースを認識させるために設定する必要がある特定のラベルがあります。

[.console-input]
[source,bash,role="copypaste",subs=attributes+]
----
oc get namespace $(oc project -q) -o jsonpath='{.metadata.labels.opendatahub\.io/dashboard}'
----
