= Llama Stack による RAG

このモジュールでは、Llama Stack の組み込み RAG 機能を使用する例を順を追って説明します。

RAG は Retrieval-Augmented Generation（検索拡張生成）の略で、LLM の知識を拡張するために頻繁に使用されるパターンです。モデルのトレーニングや微調整を行うことなく、プライベートなデータを利用できるようになります。

[NOTE]
====
**なぜ微調整ではなく RAG なのですか？** 微調整（Fine-tuning）は知識をモデルの重みに直接焼き付けますが、これにはコストと時間がかかり、データがすぐに古くなってしまいます。RAG はデータを外部の検索可能なストアに保持するため、ドキュメントを再取り込みするだけで即座に更新でき、GPU を集中的に使用するトレーニングステップも不要で、モデルが情報源を引用することも可能です。そのため、頻繁に変更されるエンタープライズナレッジベースには RAG が好まれます。
====

一般的な RAG の実装には、インジェクション（取り込み）プロセスとリトリーバル（検索）プロセスの両方が含まれます。これらをパイプラインと呼ぶこともあります。

image::rag_high_level_diagram.png[]

Llama Stack は、**Agent API** と `file_search` ツールを通じてネイティブな RAG サポートを提供します。

1. **ベクトルストアの作成 (Vector Store Creation)**: ドキュメントがアップロードされ、小さなピース（チャンク）に分割されます。
2. **埋め込みの生成 (Embedding Generation)**: 埋め込みモデルを使用して、各チャンクがベクトル埋め込みに変換されます。
3. **ベクトル検索 (Vector Search)**: クエリが実行されると、そのクエリも埋め込まれ、以下の手法で保存されたチャンクと比較されます。
   - **セマンティック検索 (Semantic search)**: ベクトルの類似性（コサイン類似度/ドット積）
   - **キーワード検索 (Keyword search)**: BM25 アルゴリズム
   - **ハイブリッド検索 (Hybrid search)**: 両方の組み合わせ（重み付け構成可能）
4. **リトリーバル/抽出 (Retrieval)**: 関連性スコアに基づいて、最も一致するチャンクが抽出されます。
5. **生成 (Generation)**: LLM は抽出されたコンテキストを使用して、出典を引用しながら回答を生成します。

**埋め込みモデルとは何ですか？** テキストを生成する LLM とは異なり、埋め込みモデル（Embedding model）はテキストを固定サイズの数値ベクトル（ここでは 768 次元）に変換します。意味が似ているテキストは、この多次元空間で互いに近いベクトルを生成します。これによりセマンティック検索が可能になります。つまり、クエリが埋め込まれ、すべてのドキュメントチャンクの埋め込みと比較されて、最も関連性の高い一致が見つけられます。

`1_create_vector_store.py` スクリプトが行うこと：

* 次の機能を使ってドキュメントを検索できる "hr-benefits-hybrid" というデータベースを作成します。
    - キーワード検索（正確な単語の検索） - 重み 50%
    - セマンティック検索（似た意味の検索） - 重み 50%

* 人事（HR）ドキュメントのダウンロード
  - GitHub から link:https://raw.githubusercontent.com/burrsutter/fantaco-redhat-one-2026/refs/heads/main/rag-llama-stack/source_docs/FantaCoFabulousHRBenefits_clean.txt[FantaCoFabulousHRBenefits_clean.txt] というテキストファイルを取得します。

* ドキュメントを Llama Stack サーバーにアップロード

* アップロードされたドキュメントのチャンク化
  - ドキュメントを小さな断片（各 100 トークン、10 トークンのオーバーラップあり）に分割します。

* ドキュメントのインデックス作成が正常に完了したかを確認するための待機

[TIP]
====
**なぜチャンク化とオーバーラップを行うのですか？** LLM にはコンテキストウィンドウの制限があり、埋め込みモデルは短い一節で最も効果的に機能します。チャンク化（Chunking）は大きなドキュメントを小さく焦点の絞られた断片に分割します。10 トークンのオーバーラップ（重ね合わせ）により、チャンクの境界で分割された文も両方のチャンクにコンテキストを持つようになり、端の部分で情報が失われる可能性を低減します。

**なぜハイブリッド検索なのですか？** キーワード検索 (BM25) は、製品名やポリシー番号などの正確な用語を見つけるのに優れています。セマンティック検索は、異なる単語が使われていても概念的に類似したコンテンツを見つけます。50/50 の重み付けにより、両方の長所を組み合わせることができます。
====

RAG パターンには通常 2 つのフェーズがあります。まず取り込み（Ingest）を行い、次に検索（Retrieval）を拡張します。取り込みが完了したので、次は検索です。

以下は、Llama Stack クライアントの Agent API と `file_search` ツールを使用した検索プロセスの例です。

[source,python]
----
agent = Agent(
    client,
    model=INFERENCE_MODEL,
    instructions="You MUST use the file_search tool to answer ALL \
questions by searching the provided documents.",
    tools=[
        {
            "type": "file_search",
            "vector_store_ids": [vector_store.id],
        }
    ],
)
----

[TIP]
====
**これはどのように動作しますか？** `Agent` は、作成したベクトルストアを指す `file_search` ツールを使用するように構成されています。質問をすると、エージェントは自動的に次のことを行います。(1) クエリを埋め込む、(2) ベクトルストアから最も関連性の高いチャンクを検索する、(3) それらのチャンクをコンテキストとして LLM に渡す、(4) 抽出されたコンテンツに基づいて回答を生成する。`instructions`（指示）フィールドは、トレーニングデータに頼るのではなく、*必ず* ドキュメントを検索するようにモデルに伝えています。
====
