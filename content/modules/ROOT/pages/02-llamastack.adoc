= Llama Stack のデプロイ

== Llama Stack の理解

Llama Stack は、生成 AI アプリケーションの構築とデプロイのための、オープンソースで標準化されたオピニオネーテッド（設計思想が統一された）フレームワークです。大規模言語モデルの操作に関する複雑さを抽象化する統一 API インターフェースとビルディングブロックを提供し、開発者がインフラストラクチャの管理ではなくエージェンティック AI アプリケーションの構築に集中できるようにします。

本ラボで稼働している Red Hat AI 3 の一部として、Llama Stack は Red Hat プラットフォームが提供するスケーラビリティ、セキュリティ、および運用上の卓越性を備えた、商用環境 AI ワークロードのデプロイ向けエンタープライズグレード機能をもたらします。

=== Llama Stack とは？

Llama Stack はディストリビューションの概念を中心に設計されています。ディストリビューションとは、推論エンジン、モデルプロバイダー、および検索拡張生成（RAG）、セーフティガードレール、ツール実行などの追加機能を組み合わせた事前構成済みのスタックです。各ディストリビューションは以下の要素で構成されます。

* **推論プロバイダー (Inference providers)**: vLLM、AWS Bedrock、Fireworks AI、Together AI、その他
* **メモリおよびベクトルストア (Memory and vector stores)**: 対話コンテキストと検索用
* **セーフティコンポーネント (Safety components)**: コンテンツモデレーションとガードレール
* **ツールランタイム (Tool runtime)**: 外部システムやAPIとの統合
* **エージェントフレームワーク (Agent framework)**: 多段階推論のオーケストレーション

=== なぜ Red Hat AI で Llama Stack を使用するのか？

Red Hat OpenShift 上の Llama Stack は、エンタープライズ AI デプロイメントにおいていくつかの主要な利点を提供します。

**標準化とポータビリティ (Standardization and portability)**::
統合された API により、アプリケーションコードを書き換えることなく、さまざまなモデルプロバイダー（vLLM、AWS Bedrock、Azure OpenAI）を切り替えることができます。これにより、ハイブリッドクラウドデプロイメントにおけるベンダーロックインの問題に対処できます。

**エンタープライズグレードの運用 (Enterprise-grade operations)**::
OpenShift 上で実行することで、自動化されたデプロイメント、スケーリング、モニタリング、およびセキュリティ機能が提供されます。Llama Stack オペレーター (Llama Stack operator) は、Kubernetes ネイティブなパターンを使用して、AI インフラストラクチャのライフサイクルを管理します。

**本番環境に対応したツール群 (Production-ready tooling)**::
Llama Stack には、本番環境の AI アプリケーション向けの組み込み機能が含まれています。
- **エージェントフレームワーク (Agent framework)**: ツール呼び出しと推論を備えたマルチターン対話
- **RAG サポート (RAG support)**: 知識に基づいた回答のためのベクトルストレージと検索
- **セーフティガードレール (Safety guardrails)**: コンテンツモデレーションとプロンプトインジェクション保護
- **オブザーバビリティ (Observability)**: ヘルスチェックとモニタリングを備えた OpenAPI 準拠のエンドポイント

**モデルの柔軟性 (Model flexibility)**::
単一のディストリビューションで、複数のモデルホスティングアプローチをサポートします。
- **ローカル推論 (Local inference)**: 低遅延でコスト効率の高いサービングのための vLLM の使用
- **Model-as-a-Service**: AWS Bedrock などのクラウドプロバイダーとの統合
- **混合デプロイメント (Mixed deployments)**: ワークロードの要件に基づいてローカルモデルとリモートモデルを組み合わせる

**開発者エクスペリエンス (Developer experience)**::
OpenAPI 仕様と Python、Node.js、およびその他の言語のクライアント SDK により、一貫した開発者エクスペリエンスが提供されます。同じコードが開発、ステージング、および本番環境で動作します。

=== Llama Stack ディストリビューション (Llama Stack distributions)

ディストリビューションは、Llama Stack のデプロイメントで利用可能なプロバイダーと機能を定義します。`starter` ディストリビューションには以下が含まれます。

* **推論 (Inference)**: ローカルモデルサービング用の vLLM（オプションでクラウドプロバイダーのサポートあり）
* **ベクトルデータベース (Vector databases)**: RAG およびセマンティック検索用
* **ツールランタイム (Tool runtime)**: Web 検索 (Tavily) および RAG 用の組み込みツール
* **セーフティ (Safety)**: コンテンツモデレーションとガードレール
* **エージェントオーケストレーション (Agent orchestration)**: ツール呼び出しを備えたマルチターン対話

このラボでは、主要な推論プロバイダーとして vLLM を使用する `starter` ディストリビューションを使用し、OpenShift AI の Model-as-a-Service (MaaS) 機能を使用するように構成されています。

== Llama Stack インスタンスのデプロイ (Deploying your Llama Stack instance)

まず最初に、ターミナル 1 (Terminal 1) と ターミナル 2 (Terminal 2) の両方で、提供された資格情報 `{user}` および `{password}` を使用して OpenShift クラスターにログインします。

[.console-input]
[source,bash,role="copypaste",subs=attributes+]
----
 {login_command}
----

そして、*Use insecure connections* に対し *y* と入力します。

[.console-output]
[source,bash,subs=attributes+]
----
The server uses a certificate signed by an unknown authority.
You can bypass the certificate check, but any data you send to the server could be intercepted by others.
Use insecure connections? (y/n): y
----

ユーザーでのログインに成功すると、あらかじめ作成されているプロジェクト `agentic-{user}` が表示されます。

[.console-output]
[source,bash,subs=attributes+]
----
Login successful.

You have one project on this server: "agentic-{user}"

Using project "agentic-{user}".
Welcome! See 'oc help' to get started.
----

クラスターとネームスペースには、Kind *LlamaStackDistribution* 用のカスタムリソース定義 (Custom Resource Definition: CRD) が用意されているため、独自の Llama Stack サーバーインスタンスを作成できます。

[TIP]
====
**CRD とは何ですか？** カスタムリソース定義 (Custom Resource Definition: CRD) は、新しいリソースタイプで Kubernetes API を拡張するものです。`LlamaStackDistribution` CRD は、Llama Stack サーバーを第一級の Kubernetes オブジェクト (first-class Kubernetes objects) として管理する方法を OpenShift に教えます。つまり、他の OpenShift リソースと同じ `oc apply` ワークフローを使用して、Llama Stack インスタンスの作成、更新、削除を行うことができます。
====

ターミナル 1 (Terminal 1) を使用して、LlamaStackDistribution CRD が利用可能かどうかを確認します。

[.console-input]
[source,bash,role="copypaste",subs=attributes+]
----
 oc api-resources | awk 'NR==1 || $1 ~ /llama/ {print $5 "\t" $4}' | column -t
----

[.console-output]
[source,bash,subs=attributes+]
----
KIND                    NAMESPACED
LlamaStackOperator      
LlamaStackDistribution  true
----

ラボの資料は GitHub リポジトリに保存されています。URL はこのページの リソース (Resources) セクションで確認できます。

次に、プロジェクトファイルのコピーをホームディレクトリに git clone します。

[.console-input]
[source,bash,role="copypaste",subs=attributes+]
----
cd $HOME
git clone https://github.com/burrsutter/fantaco-redhat-one-2026
cd fantaco-redhat-one-2026/
----

Red Hat OpenShift AI 3 には、サポート対象バージョンの Llama Stack Operator と、`rh-dev` という名前のサポート対象 Llama Stack ディストリビューションが付属しています。

LlamaStack のセットアップは、次のように ConfigMap と LlamaStackDistribution CR を使用して構成できます。

[.console-input]
[source,bash,role="copypaste",subs=attributes+]
----
oc apply -f llama-stack-scripts/llamastack-configmap.yaml
----

[.console-output]
[source,bash,subs=attributes+]
----
configmap/llama-stack-config created
----

[.console-input]
[source,bash,role="copypaste",subs=attributes+]
----
oc get cm
----

[.console-output]
[source,bash,subs=attributes+]
----
NAME                          DATA   AGE
config-service-cabundle       1      65m
config-trusted-cabundle       1      65m

odh-kserve-custom-ca-bundle   1      63m
odh-trusted-ca-bundle         2      64m
openshift-service-ca.crt      1      65m

[TIP]
====
**ConfigMap は何を構成しますか？** `llama-stack-config` ConfigMap には、Llama Stack ディストリビューションが使用するプロバイダー（推論エンジン、ベクトルストア、セーフティシールド）とその接続の詳細を定義する `run.yaml` ファイルが含まれています。これにより、構成がデプロイメントマニフェストから分離され、サーバーを再デプロイすることなく簡単にプロバイダーを変更できるようになります。
====

`oc` コマンドを使用して、ConfigMap 内の LlamaStack 構成を表示することもできます。

[.console-input]
[source,yaml,role="copypaste",subs=attributes+]
----
oc get configmap llama-stack-config -o jsonpath='{.data.run\.yaml}' ; echo
----

次のコマンドを使用して、提供されたリンク link:{litellm_api_base_url}[Model as a Service - MaaS^] で利用可能なモデルを確認できます。

[.console-input]
[source,yaml,role="copypaste",subs=attributes+]
----
curl -sS {litellm_api_base_url}/models   -H "Authorization: Bearer {litellm_virtual_key}" | jq
----

以下の Llama Stack サーバーのマニフェストを確認し、ターミナルにコマンドをコピー＆ペーストして実行して、Model-as-a-Service (MaaS) を使用する vLLM 用の Llama Stack ディストリビューションをインストールします。

[TIP]
====
**以下のマニフェストの主要フィールド:**

* `distribution.name: rh-dev` — サポートされているプロバイダーを事前構成する Red Hat 開発ディストリビューションを選択します。
* `port: 8321` — すべてのクライアントが接続する標準の Llama Stack サーバーポートです。
* `VLLM_API_URL` / `VLLM_API_TOKEN` — モデルがホストされている MaaS エンドポイントを Llama Stack に指定します。これにより、Llama Stack は推論リクエストを vLLM にプロキシします。
* `userConfig.configMapName` — 先ほど作成した ConfigMap にリンクし、完全なプロバイダー構成を定義します。
====

[.console-input]
[source,bash,role="copypaste",subs=attributes+]
----
oc apply -f - <<'EOF'
apiVersion: llamastack.io/v1alpha1
kind: LlamaStackDistribution
metadata:
  annotations:
    openshift.io/display-name: llamastack-distribution-vllm
  name: llamastack-distribution-vllm
  labels:
    opendatahub.io/dashboard: 'true'
spec:
  replicas: 1
  server:
    containerSpec:
      command:
        - /bin/sh
        - '-c'
        - llama stack run /etc/llama-stack/run.yaml
      env:
        - name: VLLM_TLS_VERIFY
          value: 'false'
        - name: MILVUS_DB_PATH
          value: ~/.llama/milvus.db
        - name: FMS_ORCHESTRATOR_URL
          value: 'http://localhost'
        - name: VLLM_MAX_TOKENS
          value: '4096'
        - name: VLLM_API_URL
          value: '{litellm_api_base_url}'
        - name: VLLM_API_TOKEN
          value: '{litellm_virtual_key}'
        - name: LLAMA_STACK_CONFIG_DIR
          value: /opt/app-root/src/.llama/distributions/rh/
      name: llama-stack
      port: 8321
      resources:
        limits:
          cpu: '2'
          memory: 12Gi
        requests:
          cpu: 250m
          memory: 500Mi
    distribution:
      name: rh-dev
    userConfig:
      configMapName: llama-stack-config


EOF
----

[.console-output]
[source,bash,subs=attributes+]
----
llamastackdistribution.llamastack.io/llamastack-distribution-vllm created
----

ヒント: CTRL+C を押すと、ポッドの監視を停止できます。

ターミナル 1 (Terminal 1) で、LlamaStack サービスを確認します。これを使用して、ネームスペース内の LlamaStack に接続します。

[.console-input]
[source,bash,role="copypaste",subs=attributes+]
----
oc get services
----

[.console-output]
[source,bash,subs=attributes+]
----

llamastack-distribution-vllm-service   ClusterIP   172.231.210.76   <none>        8321/TCP   3m46s
----

[NOTE]
====
**何が起きましたか？** Llama Stack Operator は、作成された `LlamaStackDistribution` カスタムリソースを検出し、Deployment（ポッドを管理）と ClusterIP サービス（クラスター内で安定した DNS 名を提供）を自動的に作成しました。アプリケーションは、ポート `8321` のサービス名 `llamastack-distribution-vllm-service` を介して Llama Stack に接続します。この URL は、残りのラボモジュール全体で使用します。
====

ポッドとサービスが表示されていれば、Llama Stack のデプロイは成功です。次の章では、Llama Stack について詳しく見ていきます。
