= エージェント - LangGraph

このモジュールを試行する前に、*バックエンドのセットアップ (Backend Setup)* および *MCP* というモジュールを完了しておく必要があります。

このモジュールでは、Node ベースの Web チャットユーザーインターフェース・フロントエンドと、Python ベースのバックエンドのデプロイに焦点を当てます。

物事をシンプルに保つため、フロントエンドとバックエンドの両方をデプロイするための Helm チャートが用意されています。

[TIP]
====
**何をデプロイしていますか？ (What are you deploying?)** Helm チャートは 2 つのポッドをデプロイします。*LangGraph FastAPI バックエンド*（推論、ツール呼び出し、および MCP 通信を処理する Python エージェント）と、*チャット UI (Chat UI)*（対話型のフロントエンドを提供する Node.js Web インターフェース）です。これらを合わせることで、ユーザーがブラウザを通じて対話できる完全なエージェントアプリケーションを形成します。
====

[NOTE]
====
**なぜエージェントは拒否したのですか？ (Why did the agent refuse?)** LangGraph バックエンドは、顧客および財務の運用のみに制限するシステムプロンプトで構成されています。一般的な知識に関する質問をされた場合、エージェントは登録されたツールのどれも役に立たないことを正しく認識し、推測による回答を拒否します。これは意図的なものです。本番環境では、エージェントが定義された範囲内に留まることが求められます。
====

== まとめ (Summary)

このモジュールでは、顧客および財務データ用の MCP サーバーに接続された LangGraph FastAPI バックエンドと、その前面にある Web ベースのチャット UI という、完全なエージェントアプリケーションスタックをデプロイしました。エージェントが自身のドメイン内に留まる様子（一般知識の質問を拒否する）、ビジネス上の質問に答えるために MCP ツールをどのように活用するか、そして Llama Stack のログを通じてエージェントの動作をどのように監視できるかを確認しました。このアーキテクチャ（チャット UI、エージェントバックエンド、MCP サーバー、ビジネスマイクロサービス）は、本番のエンタープライズ AI アプリケーションにおけるリファレンスパターンです。
