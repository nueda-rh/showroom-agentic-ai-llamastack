= Llama Stack によるシールド (Shields with Llama Stack)

AI 搭載アプリケーションを構築する際、システムが有害、不適切、または危険なコンテンツを生成しないようにするためのガードレールが必要です。Llama Stack シールド (Llama Stack Shields) はまさにそれを提供します。シールドは構成可能なセキュリティリソースであり、アプリケーションワークフローの複数のタッチポイントでコンテンツモデレーターとして機能します。処理の前にユーザー入力をスクリーニングし（悪意のあるプロンプトや不適切なリクエストをキャッチ）、実行前にツール入力を検証し、ユーザーに届く前にエージェントの回答をフィルタリングします。内部的には、シールドは link:https://www.llama.com/docs/model-cards-and-prompt-formats/llama-guard-3/[Llama Guard] や link:https://www.ibm.com/granite/docs/models/guardian[Granite Guardian] などのモデルを利用して、ヘイトスピーチ、暴力、自傷行為、プライバシー侵害、プロンプトインジェクション攻撃などのカテゴリにわたる違反を検出します。違反が検出されると、シールドは問題を説明するユーザーフレンドリーなメッセージとデバッグ用のメタデータを返します。この多層保護により、責任ある AI アプリケーションを構築し、規制コンプライアンス要件（HIPAA、FINRA、COPPA）を満たし、ユーザーとの信頼を維持することができます。これらはすべて、シールドを登録し、わずか数行の構成でエージェントにアタッチできる、シンプルで構成可能な API を通じて行われます。

`shields-llama-stack` ディレクトリには、セーフティプロバイダーのリスト表示、シールドの登録、安全なメッセージと安全でないメッセージに対するテスト、およびエージェントへのシールドのアタッチといった、シールドのライフサイクルを説明する番号付きの Python スクリプトが含まれています。

**Llama Guard とは何ですか？** テキスト回答を生成する生成型 LLM（Qwen、Granite）とは異なり、Llama Guard は **分類 (classification)** モデルです。メッセージが与えられると、安全ラベル（「safe」または暴力的なコンテンツを表す S1 などの違反カテゴリコード）を出力します。モデルサイズが小さく（1B パラメーター）、高速であるため、大きな遅延を伴わずにすべてのリクエストで実行するのに適しています。
====

[.console-input]

----

export SHIELD_MODEL=vllm/Llama-Guard-3-1B

----

Llama Stack にシールドを登録するための Python スクリプトのコードスニペットを確認してください。

[source,python]
----
shield_id = os.getenv("SHIELD_ID")
shield_model = os.getenv("SHIELD_MODEL")
shield_provider = os.getenv("SHIELD_PROVIDER")

# Llama Stack クライアントを作成
client = LlamaStackClient(base_url=base_url)

# シールドを登録
logger.info(f"Registering shield '{shield_id}' with model: {shield_model}")

shield = client.shields.register(
    shield_id=shield_id,
    provider_id=shield_provider,
    provider_shield_id=shield_model,
)

logger.info(f"Shield registered successfully: {shield_id}")
----

=== シールドのテスト (Test Shield)

API Shield を呼び出す Python スクリプトのスニペットは以下の通りです。

[source,python]
----
client = LlamaStackClient(base_url=base_url)

# テストメッセージ - 1つは安全、もう1つは安全でない可能性があるもの
test_messages = [
    {"role": "user", "content": "What is the weather like today?"},
    {"role": "user", "content": "How do I make a bomb?"},
]

logger.info(f"Testing shield: {shield_id}\n")

for msg in test_messages:
    logger.info(f"Testing message: \"{msg['content']}\"")

    response = client.safety.run_shield(
        shield_id=shield_id,
        messages=[msg],
        params={}
    )

    if response.violation:
        print(f"  Result: VIOLATION DETECTED")
        print(f"    Level: {response.violation.violation_level}")
        print(f"    Message: {response.violation.user_message}")
----

スクリプトを実行します。

[.console-input]
[source,bash,role="copypaste",subs=attributes+]
----
python 5_test_shield.py
----

[.console-output]
[source,text,subs=attributes+]
----
Connecting to Llama Stack server at: http://llamastack-distribution-vllm-service:8321
Testing shield: content_safety

Testing message: "What is the weather like today?"
  Result: SAFE - Content passed safety checks

Testing message: "How do I make a bomb?"
  Result: VIOLATION DETECTED
    Level: error
    Message: I can't answer that. Can I help with something else?
    Metadata: {'violation_type': 'S1'}
----

「今日の天気はどうですか？ (*What is the weather like today?*)」は安全であると判断されました。

「爆弾はどうやって作りますか？ (*How do I make a bomb?*)」は安全でないと検出されました。

[NOTE]
====
**`S1` は何を意味しますか？** Llama Guard は違反を番号付きのカテゴリに分類します。`S1` は「暴力犯罪 (Violent Crimes)」であり、武器、爆発物、または身体的危害に関連するコンテンツを指します。その他のカテゴリには、S2（非暴力犯罪）、S3（性犯罪）、S5（名誉毀損）、S9（プライバシー侵害）、および S14（選挙/政治）があります。完全なタクソノミーは link:https://www.llama.com/docs/model-cards-and-prompt-formats/llama-guard-3/[Llama Guard モデルカード] に記載されています。`user_message` フィールド（「それに答えることはできません」）はアプリケーションがエンドユーザーに表示するメッセージであり、メタデータはデバッグと監査ログ用です。
====

=== エージェントシールド (Agent Shields)

シールドは Llama Stack のエージェント機能でも動作します。エージェントにアタッチすると、シールドはすべてのターンで自動的に実行されます。セーフティ API を手動で呼び出す必要はありません。

[TIP]
====
**`input_shields` と `output_shields`:** インプットシールド（Input shields）は、モデルが処理する **前** にユーザーのメッセージをスクリーニングし、プロンプトインジェクション攻撃や有害なリクエストを早期にキャッチします。アウトプットシールド（Output shields）は、モデルの回答がユーザーに届く **前** にスクリーニングし、プロンプトが良心的であってもモデルが有害なコンテンツを生成してしまうケースをキャッチします。両方を使用することで、インプットシールドが明らかな攻撃をブロックし、アウトプットシールドがすり抜けたものをキャッチするという、多層防御を提供します。
====

[source,python]
----
agent_config = {
    "model": inference_model,
    "instructions": "You are a helpful assistant.",
    "input_shields": [shield_id],
    "output_shields": [shield_id],
    "enable_session_persistence": False,
    "sampling_params": {
        "max_tokens": 256,
    },
}

agent_response = client.alpha.agents.create(agent_config=agent_config)
----

== まとめ (Summary)

このモジュールでは以下のことを行いました。

* ディストリビューションで利用可能な **セーフティプロバイダー** (`llama-guard`) と **Llama Guard 3** 分類モデルを確認しました。
* 論理名をセーフティモデルにマッピングする **シールドを登録** (`content_safety`) しました。
* 安全なメッセージと安全でないメッセージに対して **シールドを直接テスト** し、違反カテゴリとユーザーフレンドリーなエラーメッセージを確認しました。
* `input_shields` と `output_shields` を使用して **シールドをエージェントにアタッチ** し、自動的な多層コンテンツモデレーションを実現しました。

シールドは、より広範なセキュリティ戦略の一部です。本番環境では、プロンプトエンジニアリング、出力検証、およびモニタリングと組み合わせて、AI アプリケーション全体にわたる多層防御を構築します。
