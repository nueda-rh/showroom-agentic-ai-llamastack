= ワークショップ トラブルシューティング (Workshop Troubleshooting)

== LlamaStackDistribution CRD が見つからない (LlamaStackDistribution CRD Not Found)

=== 問題: LlamaStackDistribution を作成しようとしたが、次のエラーで失敗した: resource mapping not found for name: "llamastack-distribution-vllm" namespace: "" from "STDIN": no matches for kind "LlamaStackDistribution" in version "llamastack.io/v1alpha1" ensure CRDs are installed first

=== 解決策

管理者ユーザーとして「エコシステム (Ecosystem)」にアクセスし、オペレーター (Operator) をインストールして、LlamaStack オペレーター (LlamaStack Operator) がインストールされていることを確認してください。

== LlamaStack ポッドが Pending または CrashLoopBackOff のままになる (LlamaStack Pod Stuck in Pending or CrashLoopBackOff)

=== 問題: LlamaStack ポッドが Pending 状態のままになるか、CrashLoopBackOff で再起動を繰り返す

=== 解決策

ポッドのログとイベントを確認して詳細を把握します。

[source,bash]
----
oc get pods
oc describe pod <llamastack-pod-name>
oc logs -f deploy/llamastack-distribution-vllm
----

一般的な原因:

* **Pending**: PVC がバインドされていない可能性があります。`oc get pvc` を実行して、ストレージクラスが存在し、利用可能な容量があるか確認してください。
* **CrashLoopBackOff**: VLLM_URL または VLLM_API_TOKEN 環境変数が正しくない可能性があります。これらの値がワークショップの指示で提供されたものと一致しているか確認してください。
* **ImagePullBackOff**: コンテナイメージにアクセスできない可能性があります。ネットワーク接続とイメージレジストリの認証情報を確認してください。

== LlamaStack サーバーへの接続が拒否される (Connection Refused to LlamaStack Server)

=== 問題: http://llamastack-distribution-vllm-service:8321 で LlamaStack サーバーを curl しようとすると、「接続が拒否されました (Connection refused)」または「ピアによって接続がリセットされました (Connection reset by peer)」というエラーが表示される

=== 解決策

1. LlamaStack ポッドが実行中で準備完了状態であることを確認します。
+
[source,bash]
----
oc get pods -l app=llama-stack
----
+
ステータスが `Running` の `llamastack-distribution-vllm-*` という名前のポッドを探します。

2. サービスが存在することを確認します。
+
[source,bash]
----
oc get svc llamastack-distribution-vllm-service
----

3. クラスターの外部から実行している場合は、ポートフォワーディングを使用します。
+
[source,bash]
----
oc port-forward svc/llamastack-distribution-vllm-service 8321:8321
----
+
その後、代わりに `http://localhost:8321` を使用します。

4. ポッドの起動後、1〜2 分待ちます。LlamaStack は、初期化して vLLM バックエンドに登録するまで時間が必要です。

== モデルが見つからない、または推論がタイムアウトする (Model Not Found or Inference Timeout)

=== 問題: チャット補完（chat completion）API を呼び出すと、「モデルが見つかりません (Model not found)」と表示されるか、長時間待機した後にリクエストがタイムアウトする

=== 解決策

1. 利用可能なモデルをリストして、モデル名を確認します。
+
[source,bash]
----
curl -sS $LLAMA_STACK_BASE_URL/v1/models | jq '.data[].id'
----

2. リストにある正確なモデル ID を使用していることを確認してください。このワークショップの正しいモデルは `vllm/qwen3-14b` です。

3. リクエストがタイムアウトする場合、vLLM バックエンドが過負荷になっているか、応答していない可能性があります。「OpenShift AI ダッシュボード (OpenShift AI dashboard)」で「Model-as-a-Service ステータス (Model-as-a-Service status)」を確認してください。

4. 回答が長い場合は、クライアントのタイムアウト値を増やしてください。複雑なクエリの場合、モデルの応答に 30〜60 秒かかることがあります。

== MCP サーバーの登録に失敗した (MCP Server Registration Failed)

=== 問題: MCP サーバーを LlamaStack に登録しようとすると、「MCP サーバーへの接続に失敗しました (Failed to connect to MCP server)」のようなエラーが表示されるか、ツールグループ（toolgroup）が表示されない

=== 解決策

1. MCP サーバーが実行中でアクセス可能であることを確認します。
+
[source,bash]
----
curl -sS http://fantaco-customer-mcp:8001/health
curl -sS http://fantaco-finance-mcp:8002/health
----

2. MCP サーバーの URL が正しいことを確認してください。クラスター内からは、localhost ではなくサービス名（例: `http://fantaco-customer-mcp:8001`）を使用してください。

3. HTTP ベースの MCP サーバーには、stdio ではなく SSE トランスポートを使用していることを確認してください。
+
[source,bash]
----
curl -X POST $LLAMA_STACK_BASE_URL/v1/toolgroups/register \
  -H "Content-Type: application/json" \
  -d '{
    "toolgroup_id": "customer-tools",
    "provider_id": "mcp-sse",
    "mcp_endpoint": {"uri": "http://fantaco-customer-mcp:8001/sse"}
  }'
----

4. 登録後、数秒待ってから次のように確認します。
+
[source,bash]
----
curl -sS $LLAMA_STACK_BASE_URL/v1/toolgroups | jq
----

== ベクターストアの作成に失敗する (Vector Store Creation Fails)

=== 問題: RAG の例を実行すると、埋め込み (embeddings) に関するエラーでベクターストアの作成に失敗するか、ストアが作成されない

=== 解決策

1. 埋め込みモデルが利用可能であることを確認します。
+
[source,bash]
----
curl -sS $LLAMA_STACK_BASE_URL/v1/models | jq '.data[] | select(.id | contains("embed"))'
----

2. PVC に十分なディスク容量があることを確認します。
+
[source,bash]
----
oc exec deployment/llamastack-distribution-vllm -- df -h /opt/app-root/src/.llama
----

3. ベクターストアが部分的に作成された場合は、再試行する前にリストを表示して削除してください。
+
[source,bash]
----
curl -sS $LLAMA_STACK_BASE_URL/v1/vector_stores | jq
curl -X DELETE $LLAMA_STACK_BASE_URL/v1/vector_stores/<store-id>
----

== バックエンドマイクロサービスが応答しない (Backend Microservices Not Responding)

=== 問題: FantaCo の顧客または財務 API が接続エラーを返すか、404 レスポンスを返す

=== 解決策

1. すべてのバックエンドポッドが実行されていることを確認します。
+
[source,bash]
----
oc get pods | grep fantaco
----

2. サービスが存在することを確認します。
+
[source,bash]
----
oc get svc | grep fantaco
----

3. データベースポッドが正常であることを確認します。
+
[source,bash]
----
oc get pods | grep postgres
----

4. バックエンド API を直接テストします。
+
[source,bash]
----
export CUST_URL=http://fantaco-customer-api:8000
curl -sS $CUST_URL/health
----

5. ポッドがクラッシュしている場合は、ログを確認してください。
+
[source,bash]
----
oc logs deployment/fantaco-customer-api
----

== ファイル検索の結果が返されない (File Search Returns No Results)

=== 問題: エージェントが file_search ツールを使用しているが、コンテンツが存在するはずなのに「関連する情報が見つかりませんでした (I couldn't find any relevant information)」と返される

=== 解決策

1. ベクターストアが作成され、ファイルが含まれていることを確認します。
+
[source,bash]
----
curl -sS $LLAMA_STACK_BASE_URL/v1/vector_stores | jq '.data[] | {id, name, file_counts}'
----

2. ファイルが正常に取り込まれたことを確認します（ステータスが "completed" である必要があります）。
+
[source,bash]
----
curl -sS $LLAMA_STACK_BASE_URL/v1/vector_stores/<store-id>/files | jq
----

3. よりシンプルで具体的なクエリを試してください。セマンティック検索は、単一のキーワードよりも自然言語の質問で最適に機能します。

4. ベクターストアが空の場合は、取り込みスクリプトを再実行してください。
+
[source,bash]
----
python 1_create_vector_store.py
----

== 環境変数が設定されていない (Environment Variables Not Set)

=== 問題: コマンドが「LLAMA_STACK_BASE_URL: 未定義の変数 (unbound variable)」などのエラーで失敗するか、API 呼び出しが間違った URL に送信される

=== 解決策

各ターミナルセッションの開始時に、必要な環境変数を設定します。

[source,bash]
----
export LLAMA_STACK_BASE_URL=http://llamastack-distribution-vllm-service:8321
export INFERENCE_MODEL=vllm/qwen3-14b
----

バックエンドサービスの場合:

[source,bash]
----
export CUST_URL=http://fantaco-customer-api:8000
export FIN_URL=http://fantaco-finance-api:8000
----

これらを `.bashrc` または `.zshrc` に追加して、セッション間で永続化させることができます。
