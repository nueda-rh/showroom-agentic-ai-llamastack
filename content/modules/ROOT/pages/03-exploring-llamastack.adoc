= Llama Stack の探索

Llama Stack インスタンスのデプロイに成功しましたので、API とのハンズオン形式のインタラクションを通じて、その機能を探索してみましょう。このモジュールでは、Llama Stack サーバーへの接続方法、利用可能なモデルと API の検出方法、および推論エンドポイントとの対話方法について学習します。

Llama Stack は、さまざまなユースケースに合わせて複数の API インターフェースを提供します。

* **推論 API (Inference APIs)**: 言語モデルを使用して回答を生成します。
* **エージェント API (Agent APIs)**: ツール呼び出しを備えたマルチターン対話型エージェントを構築します。
* **RAG API (RAG APIs)**: ベクトルデータベースを使用した検索拡張生成 (Retrieval-Augmented Generation) を行います。
* **セーフティ API (Safety APIs)**: コンテンツモデレーションとガードレールを提供します。
* **ツール API (Tool APIs)**: 外部機能を統合します。

この探索により、Llama Stack の API ランドスケープを理解し、エージェントアプリケーション構築の準備を整えることができます。

== Llama Stack への接続 (Connecting to Llama Stack)

[.console-input]
[source,bash,role="copypaste",subs=attributes+]
----
export LLAMA_STACK_BASE_URL=http://llamastack-distribution-vllm-service.agentic-{user}.svc:8321
export INFERENCE_MODEL=vllm/qwen3-14b
----

[.console-input]
[source,bash,role="copypaste",subs=attributes+]
----
echo "LLAMA_STACK_BASE_URL="$LLAMA_STACK_BASE_URL
echo "INFERENCE_MODEL="$INFERENCE_MODEL
----

[.console-output]
[source,bash,subs=attributes+]
----
LLAMA_STACK_BASE_URL=http://llamastack-distribution-vllm-service.agentic-{user}.svc:8321
INFERENCE_MODEL=vllm/qwen3-14b
----

Llama Stack サーバーは、ポート 8321 の内部 Kubernetes サービス URL を介してアクセスできます。`INFERENCE_MODEL` 変数は、推論リクエストに使用するモデルを指定します。このラボでは、主に Qwen3-14B モデルを使用します。

[TIP]
====
**サービス URL の読み方:** `http://llamastack-distribution-vllm-service.agentic-{user}.svc:8321` は、Kubernetes の DNS 慣習である `<サービス名>.<ネームスペース>.svc:<ポート>` に従っています。これは、リクエストがクラスターネットワーク内に留まることを意味し、外部ルーティングや認証は不要です。
====

Llama Stack ディストリビューションは、MaaS (Model-as-a-Service) アーキテクチャを介してモデルホスティング専用の Red Hat OpenShift AI クラスター上で実行されている、複数の vLLM ホストモデル（例：`qwen3-14b`、`llama-scout-17b`）へのアクセスを提供します。

**リスト内のモデルタイプ:** モデルが 2 つのカテゴリに分類されていることに注目してください。**埋め込み (Embedding)** モデル（`nomic-embed-text` など）は、テキストを検索および抽出用の数値ベクトルに変換します。これらは RAG モジュールで使用します。**LLM** モデル（`qwen3-14b`、`granite-4-0-h-tiny` など）は、テキスト回答を生成する言語モデルです。`Llama-Guard-3-1B` は、コンテンツモデレーションに使用される特殊なセーフティモデルです。
====

== 推論 API (Inference APIs)

Llama Stack は、さまざまなアプリケーションのニーズに合わせて複数の推論 API を提供します。大規模言語モデルから回答を得るための 2 つの主要なアプローチを探索してみましょう。

=== ChatCompletions API

ChatCompletions API は、対話のための OpenAI 互換インターフェースを提供します。この API は、OpenAI の GPT モデルを使用したことがある開発者にとって馴染みがあり、ストリーミング、関数呼び出し、およびマルチターン対話をサポートしています。

[.console-input]
[source,bash,role="copypaste",subs=attributes+]
----
export QUESTION="what model are you?"
----

`v1/chat/completions` や `v1/responses` などの OpenAI 互換 API には API_KEY が必要です。Llama Stack を vLLM と共に使用し、セルフホストのプライベートモデルを使用しているため、実際には使用されませんが、任意の文字列を設定できます。

[TIP]
====
**なぜ `temperature: 0.0` なのですか？** `temperature` パラメーターは、モデルの回答におけるランダム性を制御します。`0.0` の場合、モデルは常に最も可能性の高い次のトークンを選択し、確定的（再現可能）な出力を提供します。より高い値（例：`0.7`）は、より創造的または多様な回答のためにランダム性を導入します。テストや評価では、毎回同じ回答が得られる `0.0` が便利です。
====

[.console-input]
[source,bash,role="copypaste",subs=attributes+]
----
export API_KEY="not-applicable"
----

[.console-input]
[source,bash,role="copypaste",subs=attributes+]
----
curl -sS $LLAMA_STACK_BASE_URL/v1/chat/completions \
    -H "Content-Type: application/json" \
    -H "Authorization: Bearer $API_KEY" \
    -d "{
       \"model\": \"$INFERENCE_MODEL\",
       \"messages\": [{\"role\": \"user\", \"content\": \"$QUESTION\"}],
       \"temperature\": 0.0
     }" | jq -r '.choices[0].message.content'
----

[.console-output]
[source,bash,subs=attributes+]
----
I am Qwen, a large language model developed by Alibaba Cloud. I can answer
questions, create text, and assist with various tasks. How can I help you today?
----

`INFERENCE_MODEL` を変更して再度試してください。

[.console-input]
[source,bash,role="copypaste",subs=attributes+]
----
export INFERENCE_MODEL=vllm/granite-4-0-h-tiny
----

[.console-input]
[source,bash,role="copypaste",subs=attributes+]
----
curl -sS $LLAMA_STACK_BASE_URL/v1/chat/completions \
    -H "Content-Type: application/json" \
    -H "Authorization: Bearer $API_KEY" \
    -d "{
       \"model\": \"$INFERENCE_MODEL\",
       \"messages\": [{\"role\": \"user\", \"content\": \"$QUESTION\"}],
       \"temperature\": 0.0
     }" | jq -r '.choices[0].message.content'
----

[.console-output]
[source,bash,subs=attributes+]
----

of tasks such as answering questions, providing explanations, and helping with writing
and research. My exact model name isn't publicly disclosed. However, I'm designed to
provide accurate, relevant, and helpful information across a wide range of topics.
----

[NOTE]
====
**プロバイダー抽象化の動作:** まったく同じ `curl` コマンドを使用し、`INFERENCE_MODEL` 環境変数のみを変更したことに注目してください。Llama Stack は舞台裏でリクエストをまったく異なるモデルにルーティングしました。これが統合 API の核心的な価値です。モデルを入れ替えてもアプリケーションコードを変更する必要はありません。
====

[.console-input]
[source,bash,role="copypaste",subs=attributes+]
----

----

=== Responses API

OpenAI 互換の **Responses API** (`/v1/responses`) は OpenAI によって開発され、Llama Stack を通じても利用可能です。これは、AI アプリケーション向けに、より効率化され、目的に特化したインターフェースを表しています。対話パターンに焦点を当てた ChatCompletions API とは異なり、Responses API は、言語モデルとの直接的で構造化されたインタラクションが必要な現代のエージェント型ワークフロー向けに設計されています。Responses は、歴史的な ChatCompletions API の後継とみなされています。

Llama Stack は、エージェント推論のための強力なツールとしての定評ある人気から、Responses API を採用しました。この API を使用すると、複数のツールのエンドポイントや識別子をやりくりする必要がなくなります。ツールの検出、実行計画、および回答の統合を自動的に処理する 1 つの API 呼び出しを行います。Responses API は、以前はレガシー API で大規模なカスタムオーケストレーションを必要としていた、多段階の推論や自動ツールチェーンなどの高度なパターンをサポートします。

重要：LlamaStack は Response API を優先し、Agent API を非推奨にする予定です。現在、LlamaStack クライアントは移行に備えて Response API を指すように実装が変更されていますが、近い将来 Agent API は利用できなくなります。推奨される解決策は、Response API または `LegacyAgent` API を直接使用するか、Response API をラップする独自のクラスを作成することです。詳細な例については、こちらの link:https://developers.redhat.com/articles/2025/12/09/your-ai-agents-evolved-modernize-llama-stack-agents-migrating-responses-api#the_compatibility_bridge__emulating_legacy_apis[記事^] を参照してください。このラボは必要に応じて適宜更新されます。

.Responses API ワークフロー (Responses API workflow)
[mermaid,width=100%]
----
sequenceDiagram
    participant App as アプリケーション (Your Application)
    participant LS as Llama Stack サーバー (Llama Stack Server)
    participant Model as vLLM モデル (vLLM Model)
    participant Tools as 外部ツール (External Tools)

    App->>LS: POST /v1/responses<br/>{model, input}
    LS->>LS: セーフティシールドを適用
    LS->>Model: 推論プロバイダーに転送
    Model->>Model: 回答を生成
    Model-->>LS: 生のモデル出力
    LS->>LS: 出力を構造化
    LS->>Tools: (任意) ツールを実行
    Tools-->>LS: ツール実行結果
    LS-->>App: {output: [{content}]}

    Note over App,Tools: Response API がオーケストレーション、<br/>セーフティ、およびツール実行を処理します
----

#### Llama Stack の Responses API サポート (Llama Stack's Responses API support)

Llama Stack の Responses API 実装の主な機能：

* **プロバイダー抽象化 (Provider abstraction)**: 構成された任意の推論プロバイダーで同じ API が動作します
* **構造化出力 (Structured outputs)**: JSON スキーマ、構造化データ抽出、および構造化入力/出力のネイティブサポート
* **ツール統合 (Tool integration)**: RAG、Web 検索、およびカスタムツールの組み込みサポート
* **オブザーバビリティ (Observability)**: OpenAPI エンドポイントを介したリクエスト/レスポンスのロギングとモニタリング

Responses API と対話してみましょう。

[.console-input]
[source,bash,role="copypaste",subs=attributes+]
----
export QUESTION="What is the capital of Italy?"
----

[.console-input]
[source,bash,role="copypaste",subs=attributes+]
----
curl -sS "$LLAMA_STACK_BASE_URL/v1/responses" \
    -H "Content-Type: application/json" \
    -H "Authorization: Bearer $API_KEY" \
    -d "{
      \"model\": \"$INFERENCE_MODEL\",
      \"input\": \"$QUESTION\"
    }" | jq -r '.output[0].content[0].text'
----

[.console-output]
[source,bash,subs=attributes+]
----
The capital of Italy is **Rome**. It is a historic city known for its rich cultural heritage, ancient landmarks like the Colosseum and Vatican City, and its role as the political and administrative center of the country.
----

Responses API は、モデルの回答を得るためのクリーンで直接的なインターフェースを提供します。メッセージ配列を管理するのではなく、`model` と `input` を指定するという、ChatCompletion と比較して簡素化されたリクエスト構造に注目してください。レスポンスは出力コンテンツの配列として構造化されているため、テキストの抽出、ツール呼び出しの処理、または構造化データの処理が容易になります。

この API は、多段階の推論とツール実行の基盤として Responses API を使用する Llama Stack のエージェントフレームワークと組み合わせると、さらに強力になります。

== ツールランタイムと機能 (Tool runtime and capabilities)

推論以外にも、Llama Stack はエージェントが外部システムと対話するために使用できるツールのランタイム環境を提供します。これらのツールは、Web 検索、データベースへのクエリ、計算の実行、およびエンタープライズシステムとの統合を可能にすることで、言語モデルの機能を拡張します。

=== 利用可能なツールグループ (Available tool groups)

[.console-input]
[source,bash,role="copypaste",subs=attributes+]
----
curl -sS -H "Content-Type: application/json" $LLAMA_STACK_BASE_URL/v1/toolgroups | jq
----

[.console-output]
[source,json,subs=attributes+]
----
{
  "data": []
}
----

[TIP]
====
**なぜツールグループが空なのですか？** Llama Stack は、デフォルトではツールが登録されていない状態で起動します。これは意図的なもので、ツールは明示的に選択して使用する機能です。ここで登録することで、エージェントが推論プロセス中にそれらを検出し、呼び出すことができるようになります。これは、エージェントに特定の外部機能を使用する許可を与えるものと考えてください。
====

RAG と Web 検索ツールを登録します。

[.console-input]
[source,bash,role="copypaste",subs=attributes+]
----
curl -sS -X POST "$LLAMA_STACK_BASE_URL/v1/toolgroups" \
  -H "Content-Type: application/json" \
  -d '{"toolgroup_id": "builtin::rag", "provider_id": "rag-runtime"}' \
  -w "\nHTTP Status: %{http_code}\n"
----

[.console-output]
[source,bash,subs=attributes+]
----
null
HTTP Status: 200

現時点では、この Llama Stack インスタンスにデプロイおよび登録されている MCP サーバーは**ありません**。

モデルコンテキストプロトコル (Model Context Protocol: MCP) は、外部ツールやデータソースを言語モデルと統合するためのオープンな標準です。このインスタンスにはまだ MCP サーバーが構成されていませんが、このラボの後半にある専用の MCP モジュールで、MCP 機能を追加する方法を学びます。

== まとめ (Summary)

このモジュールでは、ハンズオン形式のインタラクションを通じて Llama Stack API ランドスケープを探索しました。

* **Llama Stack に接続**し、ローカルおよびクラウドプロバイダー全体で利用可能なモデルを検出しました。
* 推論、エージェント、RAG、セーフティ、およびツールに関する 100 以上のエンドポイントを持つ **API サーフェスを探索**しました。
* ChatCompletion API と Responses API の間で**推論アプローチを比較**しました。
* **Responses API を、プロバイダーの抽象化と簡素化されたセマンティクスを備えた、エージェント型ワークフローのための Llama Stack ネイティブインターフェースとして強調**しました。

次のモジュールでは、これらの API を使用して RAG を実装し、MCP を介してツールを統合し、完全なエージェントアプリケーションを構築します。
